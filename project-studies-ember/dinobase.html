A searchable dinosaur catalogue with a protected admin area

A four-person PHP/MySQL project: a searchable catalogue of dinosaur records, with a public gallery and a protected administration area.

The DinoBase

One catalogue, two audiences

The DinoBase serves two audiences — visitors who browse and search the collection, and the administrators who keep it accurate. Built by a team of four for a PHP/MySQL course, it runs as a complete Docker stack. I worked across the database and the PHP behind it: the schema, the search and pagination the gallery depends on, and the forms that write records back.

What it does

  • Search and filtering. Browse records by genus, species, era, size, weight and location, with paginated results.
  • Protected administration. Administrators maintain the catalogue behind sessions and hashed passwords, with no public registration.
  • Structured entries. Validated forms collect dinosaur details and images before saving records to the gallery.
  • Shared data. A normalized MySQL schema supports the public gallery and administration area.
  • A complete local stack. Docker packages PHP, Apache and MySQL so the application starts with a single command.

The schema is normalized around what the catalogue actually contains — dinosaurs, administrators, favourites and profile images — so each record is stored once and read wherever it is needed. Search and filtering run across genus, species, era, size, weight and location, and the gallery paginates the results. Every query that takes user input goes through prepared statements, and the admin forms validate their fields before a record is written.

The public gallery and the administration area read the same data through different paths: one is open, the other sits behind a session and hashed passwords. Docker packages MySQL, PHP and Apache, so the whole application starts locally with a single command.
